# Handoff Notes — Clothing Store Inventory System

Java 17 + JavaFX + SQLite desktop app. This document is for whoever picks up development next (human or AI) — it lists what's verified, what's been fixed/added across follow-up passes, and what's still open.

## What's verified

- All source files compile cleanly against real JavaFX 21 + SQLite JDBC jars.
- **AtlantaFX specifically**: I couldn't reach Maven Central from this sandbox, so I downloaded AtlantaFX 2.0.1's actual source from GitHub, compiled it myself, and compile-tested `App.java` against those real class files (not just docs/memory). It compiles clean and runs clean under a virtual display -- the only warning is a missing CSS resource, which is an artifact of my hand-built jar (AtlantaFX's CSS is generated by a Sass build step I didn't run), not a problem with the real Maven dependency. **Because of this, run `mvn clean javafx:run` yourself once and confirm the Cupertino Light theme actually renders (fonts, colors, rounded corners) before assuming it's fully working end to end.**
- The full class wiring (App → services → DAOs → UI) runs for several seconds under a virtual display with no exceptions, across every pass of changes below.
- A real CSS bug was caught during this testing and fixed: `styles.css` originally tried `-fx-background-color: -color-bg-default, white;` as a "use theme color, fall back to white" pattern -- JavaFX CSS doesn't support that; comma-separated values mean stacked layers, not fallback, and it threw a `ClassCastException` at runtime. Fixed to a plain literal color.
- Fixed early on: SQLite driver wasn't auto-registering because JavaFX's Application thread uses a different context classloader than the one that loaded the driver jar -- fixed with an explicit `Class.forName("org.sqlite.JDBC")` in `DatabaseManager`.

## Pass 2 fixes (robustness)

1. **Form validation** -- `ItemFormDialog` rejects blank SKU/name/category and negative or non-numeric price/quantity/reorder-threshold, showing all problems at once.
2. **UI error handling** -- `InventoryView` and `CheckoutView` catch `DataAccessException` around add/edit/delete/restock/checkout and show a friendly `Alert`.
3. **Real restock flow with audit logging** -- quantity-input dialog, logs a `RESTOCK` row to `stock_transactions` via `InventoryService.restockItem()`.
4. **Order history + cancellation** -- `OrdersView` lists orders, shows line items, cancels a `COMPLETED` order (restocks + logs `CANCELLATION`, one transaction).
5. **Category management** -- `CategoryManagerDialog` adds/deletes categories.
6. **Inventory search** -- live filter by name/SKU (`FilteredList`).
7. **Clean shutdown** -- `DatabaseManager.closeConnection()` on window close.

## Pass 3 addition (item photos)

8. **Image upload for items** -- `util/ImageStorage` copies a picked photo into `images/` (UUID filename), stored as `Item.imagePath`. `ItemFormDialog` has a preview + "Choose Image..." button (copies only on Save). `ui/ThumbnailCell` renders a 40x40 thumbnail in both `InventoryView` and `CheckoutView`.
   - Schema migration handled automatically: a safe `ALTER TABLE` runs on every startup, swallowing "column already exists" after the first run.

## Pass 4 addition (UI modernization + SKU automation + checkout safety)

**Note on scope:** the original spec for this pass asked for FlatLaf, which is Swing-only and has no effect in a JavaFX app. The user confirmed staying on JavaFX, so everything below is the JavaFX-native equivalent of each ask.

9. **AtlantaFX theme** -- `App.java` applies `CupertinoLight` (Mac-like flat theme) via `Application.setUserAgentStylesheet(...)`. Swap to `PrimerLight` for a cleaner GitHub-style look if preferred -- both are in `atlantafx.base.theme`.
10. **Status pill badges** -- new `StatusBadgeCell` (the JavaFX equivalent of a Swing `TableCellRenderer`) renders `ItemStatus` as a colored rounded pill (green/orange/red/gray) instead of plain text, used in both `InventoryView` and `DashboardView`'s low-stock table. Colors/shape defined in `styles.css` (`.status-badge` + per-status classes).
11. **Dashboard KPI cards restyled** -- `styles.css` `.kpi-card` gives rounded corners, a border, and a subtle drop shadow; each card now has an icon glyph (Unicode emoji, not Ikonli -- see note below) next to the value.
12. **SKU auto-generation** -- in `ItemFormDialog`, adding a new item auto-fills the SKU (e.g. `TOP-BLA-M-001`) as you pick category/color/size, using first-3-letters abbreviation + a sequence number based on existing matching items. Stops auto-updating the moment you type into the SKU field yourself, so manual overrides are never clobbered. Only active for new items -- editing an existing item never touches its SKU automatically.
13. **Add to Cart quantity + inline edit validation** -- Checkout's "Add to Cart" now asks for a quantity (was always +1) and checks it against both live stock AND what's already in the cart. The cart's inline quantity edit now rejects zero/negative and over-stock edits with a clear alert instead of silently clamping.

### Ikonli was left out of the actual code (dependency still in `pom.xml` for later)

Ikonli's icon constants (e.g. `Material2AL.SOMETHING`) couldn't be verified against a real jar in this sandbox the way AtlantaFX was, and guessing exact icon names risked shipping a compile error. KPI cards use plain Unicode glyphs (📦 ⚠️ ❌ 💰) instead, which are guaranteed to compile and render. Swapping to real Ikonli icon fonts later is a small, isolated change confined to `DashboardView.card(...)`.

### Lombok and OpenPDF: dependencies added, not yet wired into code

Both are in `pom.xml` as requested, but I didn't retrofit existing model classes with Lombok annotations (risk of touching many already-tested files for a cosmetic change I couldn't compile-verify against a real Lombok annotation processor here) or implement receipt PDF generation with OpenPDF (a genuinely new feature, out of scope for this pass). Both are reasonable next steps -- OpenPDF receipt printing in particular pairs naturally with `OrderService.checkout()`'s return value.

## Still not tested end-to-end

- Actually running `mvn clean javafx:run` on a real machine and eyeballing the AtlantaFX theme, badges, and KPI cards render as intended (compile/wiring is verified; visual appearance is not, since this sandbox has no real display and an incomplete AtlantaFX CSS build)
- `jpackage` build producing an actual `.exe`
- Behavior with a large catalog or many item photos

## Known gaps still open

1. Single shared `Connection`, no pooling -- fine for one user, not for concurrent access.
2. No backup/export option for `inventory.db` or `images/`.
3. Currency symbol (₱) hardcoded.
4. Deleting an item referenced by an order fails on the FK constraint (by design, but no "archive instead" option).
5. Picked images aren't resized/compressed before copying.
6. Ikonli icons, Lombok annotations, and OpenPDF receipts are scaffolded (dependency present) but not implemented -- see Pass 4 notes above.

## Where things live (quick map)

```
model/    → Item, Category, Order, OrderItem, ItemStatus (enum), StockSummary/OrderLineRequest (records)
dao/      → JDBC access; ItemDao, OrderDao, CategoryDao, StockTransactionDao, DatabaseManager
service/  → InventoryService (CRUD + restock + dashboard stats), OrderService (checkout + cancellation)
ui/       → DashboardView, InventoryView, CheckoutView, OrdersView, ItemFormDialog, CategoryManagerDialog,
            CartLine, ThumbnailCell, StatusBadgeCell
util/     → ImageStorage (copies picked photos into images/)
resources/→ schema.sql, styles.css (badges + KPI cards + nav sidebar)
App.java  → wires it all together, applies AtlantaFX theme, no login/setup screen by design
```
